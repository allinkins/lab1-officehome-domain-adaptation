# Лабораторная работа 1

Тема ВКР: **Сравнительный анализ методов выравнивания распределений для адаптации домена в задачах компьютерного зрения**.

Проект сравнивает семь мультимодальных генеративных языковых моделей как автоматических разметчиков и проверяет влияние выбранного источника псевдометок на MMD и CORAL. Требования исходного задания сопоставлены с артефактами в `REQUIREMENTS.md`.

Готовый отчёт: `Лабораторная_1_Office_Home.docx`; копия для просмотра: `Лабораторная_1_Office_Home.pdf`. В Word-отчёт включены 15 библиографических записей со ссылками на первоисточники, краткая сравнительная матрица, схема отбора работ, таблицы результатов и ограничения. Полная матрица с данными, протоколами, метриками и ограничениями находится в `literature/matrix.csv`; библиография также доступна в `literature/references_gost.txt` и `literature/references.bib`. Репозиторий: https://github.com/allinkins/lab1-officehome-domain-adaptation.

## Запуск

Python 3.12, PyTorch 2.8.0, torchvision 0.23.0, transformers 4.57.1, datasets 4.3.0, huggingface-hub 0.36.0, accelerate 1.11.0. Точный журнал среды: `configs/environment_freeze.txt`. Исходные расчёты выполняются на Apple Silicon с 16 GiB общей памяти и MPS. CUDA выбирается автоматически, если доступна. Скорость и память разных устройств напрямую не сопоставимы.

Основной ноутбук для просмотра результатов — `Лабораторная_1_анализ.ipynb`: он читает сохранённые ответы и таблицы, проверяет состав данных и выводит сводки и графики. Вывод мультимодальных моделей и обучение классификатора выполнены программами в `src`. Дополнительный `Повторный запуск.ipynb` — сценарий полного повторного запуска в отдельном рабочем каталоге; он не служит источником результатов отчёта. Для Qwen проверяется нативная поддержка bfloat16; доступность GPU и объём памяти зависят от среды. Изображения для нового запуска загружаются из зафиксированной ревизии Office-Home.

```bash
python -m venv .runtime
source .runtime/bin/activate
pip install -r requirements.txt
python src/download_data.py
python src/analyze_data.py
python src/verify.py
python src/download_models.py --model all
```

Последовательно выполнить для ключей `smol256`, `smol500`, `smol2_500`, `smol2_2200`, `llava500`, `qwen2_2000`, `qwen25_3000`:

```bash
python src/benchmark.py --model smol256
```

Не запускать модели одновременно при измерении задержек. Скрипт дописывает результаты и пропускает уже завершённые наблюдения. Повторение изменённого протокола требует отдельного каталога результатов; смешивание разных запусков недопустимо.

```bash

```

Отдельное разведочное сравнение с LoRA:

```bash
python src/train_lora.py --probe
python src/train_lora.py
python src/benchmark.py --model smol500 --adapter results/peft/adapter
python src/summarize_peft.py
python src/analyze_results.py
python src/verify_results.py
python src/build_notebooks.py
python src/build_report.py
```

LoRA не включается задним числом в основной выбор семи базовых моделей. Обучение адаптера и основной вывод сериализованы блокировкой `logs/accelerator.lock`. Веса сначала полностью загружаются, затем `benchmark.py` читает локальный snapshot без сетевых запросов. Сетевые обрывы возобновляются до пяти попыток; технические ошибки загрузки не считаются ответами модели.

Исправление численного сбоя зарегистрировано в `configs/runtime_amendment.json`: Qwen2-VL в float16 на MPS дал NaN logits на source_train. После source-only проверки оба Qwen исполняются в штатной точности bfloat16, остальные модели — float16. Ошибочный незавершённый запуск (156 ответов) сохранён в `logs/invalid_runs` и исключён из сравнения. JSON-парсер, изображения, инструкции и правило выбора не менялись. Прогрев новых запусков проверяет отсутствие NaN logits; его время и ответы не включены в метрики.

## Протокол оценки

Все модели получают один список из 65 классов и отвечают JSON с двумя полями: `label_id` — целое число, `confidence` — число от 0 до 1. Невалидные ответы не исправляются и считаются ошибкой классификации. Лимит — 40 новых токенов, `do_sample=False`, один луч. Few-shot использует три одинаковых для всех моделей демонстрации из source_train, классы 0, 22, 43. Классы выбраны до сравнения; три примера не покрывают все 65 категорий.

Основная метрика — Macro-F1 по 65 классам. ECE и бинарный Brier оценивают соответствие заявленной моделью уверенности правильности ответа только среди валидных ответов. Это не многоклассовый Brier и не оценка softmax распределения LLM. Вместе с ними обязательно читать долю валидных ответов.

95% интервалы рассчитаны percentile bootstrap, 2000 повторов, стратификация по классам; для сравнения few и zero используются одни индексы наблюдений. При одном объекте класса на validation такой bootstrap вырожден, поэтому для validation интервалы не заявляются. Два объекта класса на test тоже ограничивают надёжность интервалов.

Выбор происходит по source validation: сначала доля невалидных не более 10%, затем максимизация `0.6*MacroF1 + 0.2*(1-ECE) + 0.1*valid_rate + 0.1/(1+median_latency/5)`. Если ECE не определена, её компонент равен нулю. При отсутствии допустимых кандидатов лучший балл используется только в исследовательском режиме с явным сообщением о провале порога. Правило хранится в `configs/experiment.json`.

Для псевдометок требуется валидный ответ и уверенность не ниже 0,7. Это заранее установленный исследовательский порог, а не доказанная гарантия точности. Невалидные, неуверенные и неизвестные классы направляются на ручную разметку. Если validation gate не пройден, автоматическое применение в прототипе блокируется.

## Сравнение адаптации

Замороженный ResNet18 ImageNet извлекает признаки 512; обучаемое отображение 512 → 128 ReLU и классификатор на 65 классов одинаковы во всех условиях. Сравниваются отсутствие выравнивания, MMD и CORAL с псевдометками и без, по три seed. Нормализация обучается только на source_train. Epoch выбирается по source validation, а target test не используется для обучения, подбора коэффициентов или выбора модели.

Это контролируемая репликация идеи функций потерь на фиксированном backbone, а не точное воспроизведение опубликованных DAN или Deep CORAL. Псевдометки добавляют взвешенную cross-entropy и позволяют измерить их отдельный вклад. Новизна мировой литературы не заявляется.

Небольшие обученные отображения и классификаторы сохраняются в `results/adaptation/heads`, статистики нормализации source — в `results/adaptation/source_standardization.npz`. Они относятся к результатам исследования; крупные скачанные базовые веса удаляются отдельно. Для применения сохранённой головы к новому изображению нужен тот же ResNet18 IMAGENET1K_V1 и та же предобработка.

## Каталоги

`src` — код; `configs` — протокол и версии; `data` — метаданные и локальные изображения поднабора; `literature` — матрица и библиография; `results/raw` — первичные ответы моделей; `results/adaptation` — показатели, предсказания и обученные головы; `logs` — локальная диагностика. ## Состав репозитория

Для публикации достаточно исходного кода `src`, конфигураций `configs`, файлов `literature`, метаданных `data/*.json`, первичных ответов и итоговых результатов `results`, обоих ноутбуков, документации, `requirements.txt`, отчёта DOCX и PDF. В `results/peft/adapter` нужны только веса адаптера, его конфигурация и описание; токенизатор загружается вместе с базовой моделью. `data/images` и `data/resnet18_features.npz` восстанавливаются при повторном запуске. Ревизия датасета записана в `data/download_metadata.json`, ревизии моделей — в `configs/model_revisions.json`.

В Git не включаются виртуальные среды, кеши, исходные изображения Office-Home, скачанные базовые веса, локальные журналы `logs`, страницы проверки в `qa`, временные файлы Word, ZIP-архив, вложенные копии проекта и рабочие заметки. Эти исключения заданы в `.gitignore`. Содержимое `results/raw` сохраняется: без исходных ответов нельзя независимо пересчитать метрики моделей.

Скачанные веса используются временно и после завершения расчётов удаляются по решению владельца проекта. Для повторного полного запуска их потребуется скачать снова. Результаты, версии весов и код сохраняются.

После получения готового комплекта проверить контрольные суммы можно без ML-библиотек:

```bash
python src/package_delivery.py --verify
```

`ARTIFACT_MANIFEST.json` содержит SHA256 всех переданных файлов. Архив не включает виртуальные среды, скачанные базовые веса и промежуточные страницы визуальной проверки. Обученный LoRA-адаптер, 18 голов визуального классификатора, признаки и 1235 изображений сохранены.

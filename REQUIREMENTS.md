# Сверка с заданием лабораторной

Источник: «Лабораторная работа 1 Большие языковые модели (1).docx», разделы «Описание заданий» и «Требования к отчету». Сверка повторена 7 октября 2026 года по всем абзацам и таблицам документа. Числа из финансового примера не являются результатами этой работы.

**Утверждённая тема ВКР:** «Сравнительный анализ методов выравнивания распределений для адаптации домена в задачах компьютерного зрения».

**Задача лабораторной внутри темы ВКР:** оценить генеративные мультимодальные языковые модели как источники псевдометок Office-Home и проверить влияние этих псевдометок на сравнение MMD и CORAL. Это вспомогательный эксперимент ВКР, а не изменение её темы. Основной объект ВКР — методы выравнивания распределений. Сравнение LLM обязательно именно для данной лабораторной.

| Требование | Реализация и проверяемый артефакт |
|---|---|
| 10–15 источников и поисковый запрос | 15 записей `literature/matrix.json`, запросы и критерии `literature/search_log.json`, аналитический текст отчёта |
| PRISMA-подобная схема | Схема отбора зарегистрированных источников, без вымышленных чисел поисковой выдачи; это структурированный целевой, а не исчерпывающий систематический обзор |
| Матрица задача / архитектура / данные / протокол / метрики / код / ограничения / репликация | Все поля в `literature/matrix.csv`; препринты отделены от конференционных и журнальных статей |
| Источник, лицензия, объём, классы, пропуски, дубликаты, дисбаланс, время | Полный потоковый аудит 15 588 изображений; `data/download_metadata.json`, `results/data_analysis.json`, паспорт в отчёте |
| Проверка утечки и train / validation / test до сравнения | SHA256 изображения и pHash, объединение групп до разбиения; зафиксированный `data/manifest.json` и `split_lock.json` |
| 7–8 LLM | Семь конкретных генеративных мультимодальных checkpoint в `configs/experiment.json`; разные размеры одного семейства честно обозначены |
| Общий test, формат, сопоставимый бюджет | 130 одинаковых Clipart, 65 классов, строгий JSON, максимум 40 новых токенов, жадная генерация; реальные входные токены и задержки записываются |
| Zero-shot и few-shot | Обоим режимам каждой модели доступны одинаковые запросы; three-shot с тремя фиксированными Product source_train изображениями |
| PEFT при возможности | Отдельный ресурсно ограниченный эксперимент LoRA; статус выполнения и ограничения указываются по факту, без подмены LoRA обучением классификатора |
| Невалидные ответы и чувствительность инструкции | Строгий парсер без исправлений; перефразировка английской инструкции и русский вариант на одних 13 изображениях |
| Доверительные интервалы и журнал параметров | Стратифицированный bootstrap по тестовым изображениям, парное сравнение режимов; raw JSONL, версии, seed, SHA модели, процессор, токены, время |
| Заранее заданный многокритериальный выбор | Только Product validation; Macro-F1, ECE, валидность и задержка; тест не участвует в выборе |
| Новый срез и применение | Art и Real_World для переноса; Clipart target_adapt для псевдометок; MMD / CORAL / без выравнивания × с псевдометками / без них |
| Классификация, калибровка, устойчивость, latency, память или цена API | Accuracy, Macro/Weighted F1, MCC, balanced accuracy, ECE, бинарный Brier, доля ошибок формата, p50/p95 latency, RSS процесса |
| Ошибки по классу, длине, языку и типу финансового сообщения | Класс предмета; длина текстового ответа и входной последовательности (включает специальные визуальные токены); язык инструкции; визуальный домен и разрешение изображения. ## Пределы интерпретации

Семь checkpoint не означают семь независимых архитектур. Тест по два изображения каждого класса — малый пилотный эксперимент; доверительные интервалы не устраняют ограничение репрезентативности. Поднабор сбалансирован по истинным меткам при формировании benchmark, но алгоритмы адаптации не получают истинные метки target_adapt. Это curated UDA benchmark, а не полностью неразмеченный поток производственных данных.

Конкретные финансовые модели, five-shot, показатели 0,84, порог 1% и QLoRA двух моделей приведены в демонстрационном примере, а не как универсальные обязательные значения. Обязательная часть требует few-shot и PEFT «при возможности», поэтому three-shot и собственное зафиксированное правило выбора допустимы. «Десять характерных ошибок» из примера также включаются как полезный способ анализа.
